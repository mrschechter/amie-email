## Behaviour
- Chat turns call the existing composer endpoints (draft / revise with conversation history); each assistant reply must actually update subject/preview text/body and refresh the preview; show the "✓ On-brand voice / ✓ CAN-SPAM footer" chips when the assembled HTML contains the unsubscribe footer and the brand base template.
- Quick-action chips send preset prompts. "Make an SMS version" creates a new SMS template from the email's content (existing SMS template creation path) and links to it.
- "A/B a variant" duplicates the template as "<name> — Variant B" with the assistant's alternative subject/body.
- Draft/publish semantics unchanged: autosave the draft (debounced), `Saved N min ago` reflects it, Publish promotes it exactly as today. Send test uses the existing test-send dialog.
- Images: keep the Images panel accessible from both Compose (an "Images" button in the chat toolbar that inserts/uses assets) and Code.
- Styling per the canvas tokens: page bg #FAF8F5, text #4A4A4A, teal #2D7A7A (links, primary buttons), Cormorant Garamond for the template name/H1, DM Sans body; 8px radius cards, 1px #E6E1DA borders. No new npm deps. Must not regress `useAuthHeaders` memoization (see PR #9): no request loops, no flicker — the preview iframe re-renders only when body/subject actually change.
- Loading: Compose tab is the default; the page must render its shell in <1s and hydrate the preview afterwards (no blocking on the composer config query).
